Component overhead — Vue 3.5.13

Two arms, one page, one DOM. Arm A writes the row's seven elements directly; arm B wraps each one in a pass-through functional component — the same shape the Symbiote Vue adapter's hostComponent() used before lowering. A control compares the node census of both arms and refuses to report a per-instance figure if they differ.

This measures the h() path, not the SFC-compiled one, and the difference matters in a known direction. @vue/compiler-sfc gives a raw element static-prop hoisting and a patch flag; a component never gets either. So a real SFC app's arm A would be faster still, and this page UNDERSTATES what a template app saves by not wrapping. Symbiote hit exactly this once — a headless h() A/B predicted 12–14% where the device gave 25–29%.
