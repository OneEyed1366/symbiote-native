# @symbiote-native/print

A wrapper package for [SymbioteNative](../../README.md) that makes
[`expo-print`](https://github.com/expo/expo/tree/main/packages/expo-print) — printing a PDF/HTML
document (AirPrint on iOS, the print framework on Android) or rendering HTML to a PDF file —
usable from **every** adapter, React, Vue, Svelte, Solid, and Angular, not just React. Built the
same way as [`@symbiote-native/mail-composer`](../mail-composer): an `expo-modules-core`-based
wrapper (see the `symbiote-expo-native-module` project skill for the full mechanism — why
`expo-modules-core` is depended on directly and never the `expo` meta-package, why the upstream JS
is hand-ported into `core/` rather than imported, and how autolinking picks up the native module).

## Install

**New app:**

```bash
npx @symbiote-native/cli new my-app --print
```

**Existing SymbioteNative app:**

```bash
npx @symbiote-native/cli add --print
```

Either way: installs `@symbiote-native/print` and wires the native autolinking automatically —
see [`@symbiote-native/cli`](../cli).

<details>
<summary>Manual install (no CLI — installing and wiring native autolinking by hand)</summary>

```bash
npm install @symbiote-native/print
```

`expo-print` and `expo-modules-core` come along as regular, pinned dependencies — never install
either yourself, and never add the `expo` meta-package to this project (it bundles its own
Metro/Babel pipeline that conflicts with this project's own).

### Required one-time step: native autolinking wiring

Unlike a plain RN native module, `expo-print`'s native code is discovered by
`expo-modules-autolinking` — this needs wiring into the native host app **once**, covering this
package and every other `expo-modules-core` package with zero further changes:

| Platform | Touches                                                                               |
| -------- | ------------------------------------------------------------------------------------- |
| iOS      | `ios/Podfile` — add `use_expo_modules!`                                               |
| iOS      | `AppDelegate.swift` — Expo's runtime-bootstrap hook                                   |
| Android  | `settings.gradle` / `app/build.gradle` — resolve and include the Expo Gradle projects |
| Android  | `MainApplication.kt` — Expo's bootstrap hook, plus a native-module name map           |

Full mechanics live in the `symbiote-expo-native-module` skill. The per-package half of that
table — the Gradle dependency and the module map entry — is generated by
[`@symbiote-native/expo-modules-link`](../expo-modules-link) from this package's
`native-link.json` on every install.

### No permissions, no config plugin

- **No runtime permission on either platform.** Both the AirPrint sheet and Android's print
  framework are OS chrome the user drives directly — nothing our code touches needs a grant.
- **No manifest edit.** `expo-print`'s own `AndroidManifest.xml` declares nothing.
- **No config plugin.** Upstream ships none (`app.plugin.js` doesn't exist in the package) — a
  clean `native-link.json` with only the Android module entry is the whole file.

## Shape

```
src/core/                 the whole API: printAsync + selectPrinterAsync + printToFileAsync +
                          Orientation. native-module.ts resolves ExpoPrint through
                          expo-modules-core's requireNativeModule.
src/angular/              @symbiote-native/print/angular
```

`./react`, `./vue`, `./svelte`, and `./solid` are `exports`-map aliases straight onto `src/core/` —
no physical per-framework file, same reason [`@symbiote-native/mail-composer`](../mail-composer)
does the same: every export here is a stateless free function or a plain constant, nothing to wrap
in a hook, composable, or service. `./angular` stays a physical file/subpath since Angular ships
through a separate `ngc`/AOT build (`build-ngc/`).

## Use it

```ts
import { printAsync, printToFileAsync } from '@symbiote-native/print';

await printAsync({ html: '<h1>Invoice #1234</h1>' });

const { uri } = await printToFileAsync({ html: '<h1>Invoice #1234</h1>' });
```

Selecting a printer first (iOS only):

```ts
import { printAsync, selectPrinterAsync } from '@symbiote-native/print';

const { url } = await selectPrinterAsync();
await printAsync({ html: '<h1>Invoice #1234</h1>', printerUrl: url });
```

## API

| Export              | Signature                                              | Notes                                      |
| ------------------- | ------------------------------------------------------- | ------------------------------------------- |
| `printAsync`        | `(options: IPrintOptions) => Promise<void>`              | Exactly one of `uri`/`html`. One at a time. |
| `selectPrinterAsync` | `() => Promise<IPrinter>`                               | iOS only — throws elsewhere.               |
| `printToFileAsync`  | `(options?: IFilePrintOptions) => Promise<IFilePrintResult>` | Renders HTML to a PDF in the cache dir.    |
| `Orientation`       | `{ portrait: string; landscape: string }`                | Values for `IPrintOptions.orientation`.    |

## Notes

- **One print job at a time.** A second `printAsync` call while one is in flight rejects
  immediately — same guard upstream keeps as module-level state.
- **`markupFormatterIOS` was dropped.** Upstream deprecated it in favor of `useMarkupFormatter`;
  this port only carries the replacement.

## Test it

```bash
pnpm vitest run packages/print
```

The core tests fake the native module in place of `requireNativeModule`'s runtime resolution —
`ExpoPrint` only exists on a device, so a headless run would otherwise throw at import. Upstream
ships no test suite of its own (`expo-print`'s `src/` has no `__tests__`), so nothing to port —
every test here is net-new coverage of the ported logic (input validation, the in-flight guard,
the `selectPrinter`-unavailable branch).
