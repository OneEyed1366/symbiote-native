# @symbiote-native/document-picker

A wrapper package for [SymbioteNative](../../README.md) that makes
[`expo-document-picker`](https://github.com/expo/expo/tree/main/packages/expo-document-picker) —
opening the system UI for picking a document from any provider installed on the device — usable
from **every** adapter, React, Vue, Svelte, Solid, and Angular, not just React. Built the same way
as [`@symbiote-native/print`](../print): an `expo-modules-core`-based wrapper (see the
`symbiote-expo-native-module` project skill for the full mechanism — why `expo-modules-core` is
depended on directly and never the `expo` meta-package, why the upstream JS is hand-ported into
`core/` rather than imported, and how autolinking picks up the native module).

## Install

**New app:**

```bash
npx @symbiote-native/cli new my-app --document-picker
```

**Existing SymbioteNative app:**

```bash
npx @symbiote-native/cli add --document-picker
```

Either way: installs `@symbiote-native/document-picker` and wires the native autolinking
automatically — see [`@symbiote-native/cli`](../cli).

<details>
<summary>Manual install (no CLI — installing and wiring native autolinking by hand)</summary>

```bash
npm install @symbiote-native/document-picker
```

`expo-document-picker` and `expo-modules-core` come along as regular, pinned dependencies — never
install either yourself, and never add the `expo` meta-package to this project (it bundles its
own Metro/Babel pipeline that conflicts with this project's own).

### Required one-time step: native autolinking wiring

Unlike a plain RN native module, `expo-document-picker`'s native code is discovered by
`expo-modules-autolinking` — this needs wiring into the native host app **once**, covering this
package and every other `expo-modules-core` package with zero further changes:

| Platform | Touches                                                                               |
| -------- | ------------------------------------------------------------------------------------- |
| iOS      | `ios/Podfile` — add `use_expo_modules!`                                               |
| iOS      | `AppDelegate.swift` — Expo's runtime-bootstrap hook                                   |
| Android  | `settings.gradle` / `app/build.gradle` — resolve and include the Expo Gradle projects |
| Android  | `MainApplication.kt` — Expo's bootstrap hook, plus a native-module name map           |

Full mechanics live in the `symbiote-expo-native-module` skill. The per-package half of that
table — the Gradle dependency and the module map entry — is generated by
[`@symbiote-native/expo-modules-link`](../expo-modules-link) from this package's
`native-link.json` on every install.

### No runtime permission, no manifest edit

- **No runtime permission on either platform.** The system document picker is the OS's own UI;
  it runs outside the app's own permission surface.
- **No manifest edit.** `expo-document-picker`'s own `AndroidManifest.xml` declares only a
  `<queries>` block for Android 11+ package-visibility rules; it merges in automatically once the
  Gradle project is included.
- **iCloud entitlements are opt-in and not generated.** Upstream's config plugin sets
  `com.apple.developer.icloud-container-environment` and related iCloud/ubiquity entitlement
  keys, but only when the app's Expo config sets `ios.usesIcloudStorage` — off by default, and
  this project has no Expo config to read it from in the first place (same reasoning as
  `expo-notifications`' `aps-environment` entitlement — see that package's own README). If your
  app needs iCloud-backed document picking, add those entitlement keys to your own
  `Info.plist`/`.entitlements` file by hand; there is nothing here to enable.

## Shape

```
src/core/                 the whole API: getDocumentAsync. native-module.ts resolves
                          ExpoDocumentPicker through expo-modules-core's requireNativeModule.
src/angular/              @symbiote-native/document-picker/angular
```

`./react`, `./vue`, `./svelte`, and `./solid` are `exports`-map aliases straight onto `src/core/` —
no physical per-framework file, same reason [`@symbiote-native/print`](../print) does the same:
the whole surface is one stateless free function, nothing to wrap in a hook, composable, or
service. `./angular` stays a physical file/subpath since Angular ships through a separate
`ngc`/AOT build (`build-ngc/`).

## Use it

```ts
import { getDocumentAsync } from '@symbiote-native/document-picker';

const result = await getDocumentAsync({ type: 'application/pdf', multiple: true });
if (!result.canceled) {
  for (const asset of result.assets) {
    console.log(asset.name, asset.uri, asset.size);
  }
}
```

## API

| Export             | Signature                                                        | Notes                                    |
| ------------------ | ------------------------------------------------------------------ | ------------------------------------------ |
| `getDocumentAsync` | `(options?: IDocumentPickerOptions) => Promise<IDocumentPickerResult>` | Default `type` is any MIME type. |

`IDocumentPickerOptions`: `type` (string or string array, wildcards allowed), `copyToCacheDirectory`
(default `true`), `multiple` (default `false`).
`IDocumentPickerResult`: `{ canceled: true; assets: null }` or
`{ canceled: false; assets: IDocumentPickerAsset[] }`.
`IDocumentPickerAsset`: `name`, `uri`, `lastModified`, plus optional `size` and `mimeType`.

## Notes

- **Web-only fields dropped.** Upstream's `base64`/`file`/`output` fields only exist on the web
  platform; this package targets iOS/Android only, so they're not part of the port (matching
  `expo-module.config.json`'s own `platforms: ["apple", "android"]`).

## Test it

```bash
pnpm vitest run packages/document-picker
```

The core tests fake the native module in place of `requireNativeModule`'s runtime resolution —
`ExpoDocumentPicker` only exists on a device, so a headless run would otherwise throw at import.
Upstream's only test suite (`plugin/src/__tests__/withDocumentPickerIOS-test.ts`) exercises the
config-plugin's `setICloudEntitlements` function — build-time code this project doesn't carry
over (native config here is static `native-link.json`, not a plugin we run), so it isn't ported.
The tests here cover the runtime API instead: option defaults, the string→array `type` coercion,
and result delegation.
