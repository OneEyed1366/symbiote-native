# @symbiote-native/image-picker

A wrapper package for [SymbioteNative](../../README.md) that makes
[`expo-image-picker`](https://github.com/expo/expo/tree/main/packages/expo-image-picker) —
opening the system UI for picking an image/video from the library or taking one with the camera —
usable from **every** adapter, React, Vue, Svelte, Solid, and Angular, not just React. Built the
same way as [`@symbiote-native/document-picker`](../document-picker): an `expo-modules-core`-based
wrapper (see the `symbiote-expo-native-module` project skill for the full mechanism — why
`expo-modules-core` is depended on directly and never the `expo` meta-package, why the upstream JS
is hand-ported into `core/` rather than imported, and how autolinking picks up the native module).

## Install

**New app:**

```bash
npx @symbiote-native/cli new my-app --image-picker
```

**Existing SymbioteNative app:**

```bash
npx @symbiote-native/cli add --image-picker
```

Either way: installs `@symbiote-native/image-picker` and wires the native autolinking
automatically — see [`@symbiote-native/cli`](../cli).

<details>
<summary>Manual install (no CLI — installing and wiring native autolinking by hand)</summary>

```bash
npm install @symbiote-native/image-picker
```

`expo-image-picker` and `expo-modules-core` come along as regular, pinned dependencies — never
install either yourself, and never add the `expo` meta-package to this project (it bundles its
own Metro/Babel pipeline that conflicts with this project's own).

### Required one-time step: native autolinking wiring

Unlike a plain RN native module, `expo-image-picker`'s native code is discovered by
`expo-modules-autolinking` — this needs wiring into the native host app **once**, covering this
package and every other `expo-modules-core` package with zero further changes:

| Platform | Touches                                                                               |
| -------- | ------------------------------------------------------------------------------------- |
| iOS      | `ios/Podfile` — add `use_expo_modules!`                                               |
| iOS      | `AppDelegate.swift` — Expo's runtime-bootstrap hook                                   |
| Android  | `settings.gradle` / `app/build.gradle` — resolve and include the Expo Gradle projects |
| Android  | `MainApplication.kt` — Expo's bootstrap hook, plus a native-module name map           |

Full mechanics live in the `symbiote-expo-native-module` skill. The per-package half of that
table — the Gradle dependency and the module map entry — is generated by
[`@symbiote-native/expo-modules-link`](../expo-modules-link) from this package's
`native-link.json` on every install.

### Permissions this package requests

- **iOS `Info.plist` keys** (generated automatically): `NSPhotoLibraryUsageDescription`,
  `NSCameraUsageDescription`, `NSMicrophoneUsageDescription` — reword the strings in
  `native-link.json` if the defaults don't fit your app.
- **Android `RECORD_AUDIO`** (generated automatically) — needed because the camera picker can
  record video with sound. `CAMERA`, `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, and the pre-33
  storage permissions ship in `expo-image-picker`'s own `AndroidManifest.xml` and merge in
  automatically once the Gradle project is included — nothing to declare for those.

## Shape

```
src/core/                 the whole API: launchCameraAsync + launchImageLibraryAsync +
                          getPendingResultAsync + the permission functions. native-module.ts
                          resolves ExponentImagePicker through expo-modules-core's
                          requireNativeModule.
src/angular/              @symbiote-native/image-picker/angular
```

`./react`, `./vue`, `./svelte`, and `./solid` are `exports`-map aliases straight onto `src/core/` —
no physical per-framework file: every export is a stateless free function, nothing to wrap in a
hook, composable, or service. `./angular` stays a physical file/subpath since Angular ships through
a separate `ngc`/AOT build (`build-ngc/`).

## Use it

```ts
import { launchImageLibraryAsync, requestMediaLibraryPermissionsAsync } from '@symbiote-native/image-picker';

await requestMediaLibraryPermissionsAsync();
const result = await launchImageLibraryAsync({ mediaTypes: 'images', quality: 0.8 });
if (!result.canceled) {
  console.log(result.assets[0].uri);
}
```

Taking a photo:

```ts
import { launchCameraAsync, requestCameraPermissionsAsync } from '@symbiote-native/image-picker';

await requestCameraPermissionsAsync();
const result = await launchCameraAsync({ allowsEditing: true });
```

## API

| Export                              | Signature                                                         | Notes                                    |
| ------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------ |
| `launchCameraAsync`                 | `(options?: IImagePickerOptions) => Promise<IImagePickerResult>`     | Throws `UnavailabilityError` if absent.  |
| `launchImageLibraryAsync`           | `(options?: IImagePickerOptions) => Promise<IImagePickerResult>`     |                                             |
| `getCameraPermissionsAsync`         | `() => Promise<ICameraPermissionResponse>`                          |                                             |
| `requestCameraPermissionsAsync`     | `() => Promise<ICameraPermissionResponse>`                          |                                             |
| `getMediaLibraryPermissionsAsync`   | `(writeOnly?: boolean) => Promise<IMediaLibraryPermissionResponse>`  |                                             |
| `requestMediaLibraryPermissionsAsync` | `(writeOnly?: boolean) => Promise<IMediaLibraryPermissionResponse>` |                                             |
| `getPendingResultAsync`             | `() => Promise<IImagePickerResult \| IImagePickerErrorResult \| null>` | Android only — resolves `null` on iOS.   |

`IImagePickerOptions` carries the full upstream surface: `allowsEditing`, `aspect`, `shape`,
`quality`, `mediaTypes`, `exif`, `base64`, `videoExportPreset`, `videoQuality`,
`allowsMultipleSelection`, `selectionLimit`, `orderedSelection`, `defaultTab`, `videoMaxDuration`,
`presentationStyle`, `cameraType`, `preferredAssetRepresentationMode`, `legacy`,
`shouldDownloadFromNetwork`.

## Notes

- **React's `useCameraPermissions`/`useMediaLibraryPermissions` are not ported.** Upstream's
  `createPermissionHook` (`expo-modules-core`) is built on `useState`/`useEffect`/`useCallback`
  from `react` internally — a real React hook, not a framework-agnostic wrapper — so it belongs
  per-adapter, not in `core/`, per `<third_party_rn_packages_are_react_only>`. Call
  `getCameraPermissionsAsync`/`requestCameraPermissionsAsync` (and the media-library equivalents)
  directly instead; wrapping them in your own adapter's hook/composable is a few lines.
- **`allowsEditing` + `allowsMultipleSelection` together only warns**, matching upstream: the
  native side silently ignores `allowsEditing` in that case rather than throwing.
- **Deprecated `MediaTypeOptions` enum still works** (ported for parity) but logs a console
  warning pointing at the string/array `mediaTypes` form upstream now prefers.
- **Web-only fields dropped**: `ImagePickerAsset.file`, `ImagePickerResult.output`, and the
  `base64`/`capture` fields of the internal web-only options type — this package targets
  iOS/Android only, matching `expo-module.config.json`'s `platforms: ["apple", "android"]`.

## Test it

```bash
pnpm vitest run packages/image-picker
```

The core tests fake the native module in place of `requireNativeModule`'s runtime resolution —
`ExponentImagePicker` only exists on a device, so a headless run would otherwise throw at import.
Two cases are ported directly from upstream's `src/__tests__/ImagePicker-test.native.ts`
(`launchCameraAsync`/`launchImageLibraryAsync` default to an empty options object); the rest is
net-new coverage of option validation, permission delegation, and the Android-only
`getPendingResultAsync` branch. Upstream's other test suite
(`plugin/src/__tests__/withImagePicker-test.ts`) exercises the config-plugin's own internals —
build-time code this project doesn't carry over (native config here is static
`native-link.json`, not a plugin we run), so it isn't ported.
