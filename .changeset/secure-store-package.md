Add `@symbiote-native/secure-store` — a framework-agnostic wrapper around `expo-secure-store`
(built on `expo-modules-core`, never the `expo` meta-package), reachable identically from React,
Vue, and Angular. Encrypted key/value storage in the iOS Keychain and the Android Keystore:
`getItemAsync`/`setItemAsync`/`deleteItemAsync`, their synchronous `getItem`/`setItem` twins,
`isAvailableAsync`, `canUseBiometricAuthentication`, and the seven iOS `kSecAttrAccessible`
constants for `options.keychainAccessible`.

Entries can be gated behind the device's own biometrics with `requireAuthentication`. The prompt
fires at different moments per platform — Android on every operation, iOS only when reading or
updating an entry that already exists — and simulators do not enforce it at all, so that option
can only be verified on a real device.

All three adapter entry points are plain re-exports of the core: upstream ships free functions
and constants with no per-instance state and no event stream, so there is nothing for a hook,
composable, or service to wrap — the same shape `@symbiote-native/local-auth` has.

Android registration and the iOS `NSFaceIDUsageDescription` string are generated by
`@symbiote-native/expo-modules-link` from the package's `native-link.json`, along with the two
`<application>` attributes Auto Backup needs (`android:fullBackupContent`,
`android:dataExtractionRules`) — without them Android would back up the encrypted entries but not
the Keystore keys that decrypt them, leaving a restored install holding unreadable values.

First package off tier 2 of the Expo migration queue.
