`@symbiote-native/test-utils` is the harness [Testing](/docs/testing/) refers to.
`installRecordingFabric()` installs a recording tree host in place of the native one and returns a
handle to it. The handle records the nodes and calls the [engine](/docs/api/core/) produced, and its
`fireEvent` pushes a native event back into the renderer.

The recorder keeps the tree as the renderer authored it and derives nothing. It does not flatten,
clone or rename views. `createLiveTree(fabric)` reads what is on screen over that recording.

Unlike the wrapper packages documented here, such as [slider](/docs/packages/slider/), it wraps no
native library. It is a `devDependency` that runs in Node under Vitest, and no app code imports it.

## Installation

```sh
npm install -D @symbiote-native/test-utils
```

## Vitest setup

No DOM environment is needed: the tests run in Vitest's `node` environment. The default config is
not enough, because the engine imports `react-native`. React Native ships Flow source that expects
Metro and a device, and a bare run stops with `Flow is not supported`. The config has to:

- strip the Flow types from `react-native` and `@react-native/*` sources;
- resolve their platform files, such as `Platform.ios.js`;
- stub `TurboModuleRegistry` and `NativeModules`;
- define `__DEV__` in a setup file;
- list `@symbiote-native/*` and `react-native` in `server.deps.inline`.

The repository's
[`vitest.config.ts`](https://github.com/OneEyed1366/symbiote-native/blob/master/vitest.config.ts)
is a working version of all five.

## Usage

One shape works on all five adapters:

1. Install the recorder once at module scope.
2. `reset()` it between tests.
3. `mount()` the component under test and wait for the first commit.
4. Fire a native event and assert on what the screen says.

Each example below mounts a switch with a label, flips the switch and reads the label.

<Tabs syncKey="framework">
  <TabItem label="React">
    ```tsx
    import { useState } from 'react';
    import { afterEach, beforeEach, describe, expect, it } from 'vitest';
    import { mount, unmount } from '@symbiote-native/react';
    import { createLiveTree, installRecordingFabric, waitUntil } from '@symbiote-native/test-utils';

    const ROOT_TAG = 190;

    const fabric = installRecordingFabric();
    const live = createLiveTree(fabric);
    const screen = (): string[] => live.texts(live.appRoot());

    function switchHandle(): object {
      const handle = fabric.find(node => node.viewName === 'Switch')?.instanceHandle;
      if (typeof handle !== 'object' || handle === null) {
        throw new Error('no Switch was created');
      }
      return handle;
    }

    function App() {
      const [isOn, setOn] = useState(false);
      return (
        <view>
          <switch value={isOn} onValueChange={setOn} />
          <text>{isOn ? 'on' : 'off'}</text>
        </view>
      );
    }

    beforeEach(() => fabric.reset());
    afterEach(() => unmount(ROOT_TAG));

    describe('React Switch on the engine', () => {
      it('shows the new value after a native change', async () => {
        mount(ROOT_TAG, <App />);
        await waitUntil(() => fabric.commits > 0, 'first commit');
        expect(screen()).toEqual(['off']);

        fabric.fireEvent(switchHandle(), 'topChange', { value: true });
        await waitUntil(() => screen().includes('on'), 'the switch turns on');
      });
    });
    ```

## API

### Functions

| Signature | Description |
| --------- | ----------- |
| `installRecordingFabric(): IRecordingHost` | Installs the recording host and a minimal `nativeFabricUIManager`. Call it at module scope, before the first mount |
| `createRecordingHost(): IRecordingHost` | Builds the same host without installing it |
| `createLiveTree(fabric, options?): ILiveTree` | Reads the tree that is on screen. `keepBlankText: true` keeps empty raw texts |
| `payloadOf(node): Record<string, unknown>` | The Fabric payload the engine's JS builder makes for a node, with `style` flattened |
| `censusLive(...roots): ILiveCensus` | Counts a live subtree as `nodes`, `anchors` and `nonAnchors` |
| `createListHarness(fabric, live): IListHarness` | Drives a virtualized list: layout and scroll events, plus the mounted cells |
| `trackHostCrossings(host): IHostCrossingTracker` | Counts calls into the tree host, `applyOps` excluded |
| `waitUntil(condition, label, timeoutMs?)` | Polls once per macrotask and throws with `label` on timeout |
| `waitForQuiet(sample, label, options?)` | Waits until `sample()` stops changing and returns the settled value |
| `advanceTicks(count)`, `advanceMs(durationMs?)` | Lets the queue drain for a number of macrotasks or a wall-time window |
| `emitRnDeviceEvent(eventType, payload)` | Emits a React Native device event |
| `seedWindowDimensions()`, `emitWindowDimensions(window, screen?)` | Seeds or changes the window size, with `TEST_WINDOW` as the default size |
| `nativeCallsTo(moduleName)` | Reads the calls your native module stub pushed to `globalThis.__symbioteNativeCalls`, as the repository's config does. The package installs no stub |

### `IRecordingHost`

It implements the engine's tree host. These are the members a test reads or calls:

| Member | Description |
| ------ | ----------- |
| `commits` | How many commits the engine asked for |
| `commands` | Imperative view commands in order, such as the snap-back of a `Switch` |
| `responderHandovers`, `accessibilityEvents` | Logs of the matching platform calls |
| `find(predicate)`, `findAll(predicate)` | Search the nodes created since the last `reset()`, in creation order |
| `fireEvent(handle, topLevelType, nativeEvent?)` | Delivers a native event to the handler the renderer registered. Throws if none is registered |
| `answerMeasureLayout(answer)` | Sets what `measureLayout` answers. Without an answer the call fails |
| `reset()` | Clears the creation list, the counters and the logs. The authored tree survives |
| `forget()` | Does what `reset()` does and also drops the records of all nodes |

### `IAuthoredNode`

| Field | Description |
| ----- | ----------- |
| `handle` | The engine node, to pass back to the engine's own API |
| `instanceHandle` | What `fireEvent` is aimed at. `undefined` for a raw text or an anchor |
| `viewName` | The view name as the renderer asked for it. Fabric may commit it under another name |
| `tagName` | The intrinsic tag of a node with a host behavior, empty for every other node |
| `props` | The authored props. `style` is still an object |
| `ownedListeners` | Which event names a behavior owns have an app callback |
| `underlayShown` | Whether a behavior's press feedback is showing |

### `ILiveTree`

| Member | Description |
| ------ | ----------- |
| `appRoot()` | The app's own `box-none` root, found in the creation list. Throws when no mount happened since the last `reset()` |
| `nodeOf(handle)` | One node with its `viewName`, `props`, `payload` and `children` |
| `findLive(root, predicate)`, `findAllLive(root, predicate)` | Search the nodes that are on screen now |
| `walkLive(root, visit)` | Visits a subtree in pre-order |
| `serialize(root)` | One line such as `RCTView(RCTText(RCTRawText "text"))` |
| `texts(root)` | Every raw text in tree order |
| `outline(root)` | A depth-indented list of view names |

## Notes

<Aside type="caution" title="Install once per file, not once per test">
  The engine binds the Fabric slot once and caches it for the life of the module. Call
  `installRecordingFabric()` once at module scope and use `reset()` between tests. Vitest isolates
  test files from one another, so each file still starts clean.
</Aside>

- **`find()` searches the creation list, not the screen.** A node the app removed still answers it.
  Ask the live tree whether something is mounted. It follows the engine's current child links and
  skips anchors, as a commit does.
- **Keep the root before a `reset()` in the middle of a test.** `reset()` empties the creation list
  that `appRoot()` searches. Store `const root = live.appRoot()` first, then reset and read `root`.
- **The payload here is not the whole native payload.** `payloadOf()` runs the engine's JS builder.
  Platform rules written in C++ do not run, and the engine's `committedPayloadOf()` throws under
  this host. A test of the committed shape belongs in the native tests under
  `core/engine/cpp/tests/js`.
- **Nothing is measured.** No layout runs, so `measure` and `measureInWindow` never call back.
- **Prefer `waitUntil` to a fixed number of ticks.** A tick count only stands in for "the framework
  has settled" and breaks on a loaded machine.
- **This is the headless layer only.** It proves JS-side behavior and does not stand in for a real
  native host. See [Testing](/docs/testing/) for how it and the on-device Detox layer divide work.

## How the package is laid out

```
core/test-utils/src/
├── index.ts              # the public surface
├── recording-host.ts     # installRecordingFabric(), IRecordingHost, payloadOf()
├── recorded-tree.ts      # the authored tree the host keeps
├── live-tree.ts          # createLiveTree(), censusLive()
├── list-harness.ts       # createListHarness()
├── host-crossings.ts     # trackHostCrossings()
├── wait-for.ts           # waitUntil(), waitForQuiet(), advanceTicks(), advanceMs()
├── native-calls.ts       # nativeCallsTo()
├── rn-device-event.ts    # emitRnDeviceEvent()
└── window-dimensions.ts  # the window size helpers
```

It lives under `core/`, not `packages/`, because it belongs to the same layer as
[`@symbiote-native/engine`](/docs/api/core/). It has no adapter entry points: the React, Vue,
Angular, Svelte and Solid suites import the same module.
