Primitives (`view`, `text`, `pressable`, `text-input`, `scroll-view`, ...) are
plain lowercase intrinsic tags — write them directly in markup, no import
needed. Import only what's still a real component or module from
`@symbiote-native/svelte`:

```ts
import { StyleSheet } from '@symbiote-native/svelte';
```

Svelte drives the same engine as React/Vue/Angular/Solid, through Svelte's own
custom renderer API (`createRenderer` from `svelte/renderer`). The API is
experimental in Svelte itself and needs `svelte >= 5.59.1`. Components are
compiled with `experimental.customRenderer`, and every node operation routes
into `@symbiote-native/engine`'s mutation API. Components are ordinary `.svelte`
files; nothing about authoring one is adapter-specific beyond the prop/event
shape below.

The compiler rejects the constructs that need a DOM: `bind:` on an element,
`on:`, `transition:`, `in:`, `out:`, `animate:`, `{@html}` and
`<svelte:window>`, `<svelte:document>`, `<svelte:body>`, `<svelte:head>`. Use
`{@attach}`, `onX={...}` props and the runtime modules instead.

## Installation

```sh
pnpm add @symbiote-native/svelte react-native svelte
```

`react-native` and `svelte` stay your app's own top-level dependencies —
`react-native` is the Metro version anchor, so it has to be pinned at the app
root. `@symbiote-native/engine` is a peer dependency and installs alongside.
Metro needs the package's own transformer for `.svelte` files
(`@symbiote-native/svelte/metro-svelte-transformer`) and two settings that are
easy to miss: `resolver.unstable_conditionNames: ['svelte-custom-renderer',
'browser']` (without it Metro resolves Svelte's default runtime, which has no
`svelte/renderer`), and `compilerOptions` in `svelte.config.js` with
`fragments: 'tree'` and `experimental: { customRenderer:
'@symbiote-native/svelte/renderer' }`. `examples/svelte` is the reference for
the full config.

## Component shape

- Events: real camelCase **props**, not `on:x` directives — `onPress`,
  `onLongPress`, `onValueChange`, `onLayout`. Svelte templates already write
  props in camelCase, so there's no kebab-case normalization step like Vue's.
- Children: a `children` prop typed `Snippet`, rendered internally via
  `{@render children?.()}` — not Svelte 4's `<slot />`.
- Render children: list components only (`FlatList`, `SectionList`, ...) still
  pass state back via `{#snippet}` (Svelte's twin of a scoped slot); a
  primitive tag like `pressable` has no component body to render one from —
  wire `onPressIn`/`onPressOut` into a rune instead, see [Children](#children)
  below.
- Refs: `bind:this` on an element is a compile error, so a host node is
  reached through `{@attach}`. See [refs and
  attachments](/docs/howtos/svelte-refs-and-attachments/) for the full picture,
  including `hostInstance()`/`findNodeHandle()`.
- Styles: `style`/`class` props, plus a component's own scoped `<style>`
  block — see [Scoped styles](#scoped-styles-style) below.
- Two-way binding: `value` + `onValueChange` on `text-input`/`switch`, and
  `bind:value` on a component such as [`Slider`](/docs/packages/slider/).
  See [Two-way binding](#two-way-binding-bindvalue) below.

## Common events

```svelte
<pressable {onPress} {onLongPress} />
<switch value={enabled} onValueChange={event => (enabled = event.value)} />
<text-input value={text} onValueChange={event => (text = event.text)} />
<view {onLayout} />
```

`onValueChange` fires with one change-event object, the same shape React
uses: `event.text` or `event.value` carries the new value, and `event` is the
native event. Angular needs a second output for the raw event, because an
`EventEmitter` only carries one value.

## Children

`pressable` is a plain tag, so pressed state no longer arrives through a
`{#snippet}` — wire the two press events into a rune instead:

```svelte
<script lang="ts">
  let pressed = $state(false);
</script>

<pressable
  {onPress}
  onPressIn={() => (pressed = true)}
  onPressOut={() => (pressed = false)}
>
  <text>{pressed ? 'Release' : 'Press me'}</text>
</pressable>
```

List renderers still pass state back through a `{#snippet}`, since the
rendered cell is a real Svelte snippet rather than a React node or a Vue slot.

## Refs and handles

```svelte
<script lang="ts">
  let node: unknown;
</script>

<view testID="target" {@attach el => (node = el)} />
```

`bind:this` on an element is rejected at compile time, so a plain ref is an
`{@attach}` that stores the node. The attachment also takes a cleanup function
when you want a mount/unmount pair. Imperative methods like
`scroll-view`'s `scrollTo`/`scrollToEnd`/`flashScrollIndicators` live on the
host node itself — reach them through `hostInstance(node)`. Full mechanism,
including `findNodeHandle()`: [How to: refs and attachments in
Svelte](/docs/howtos/svelte-refs-and-attachments/).

## Two-way binding (`bind:value`)

`bind:` is rejected on an element, so `switch` and `text-input` take the
controlled `value` + `onValueChange` pair. A component can declare
`value = $bindable()`, and the [Slider](/docs/packages/slider/) wrapper does:

```svelte
<switch value={enabled} onValueChange={event => (enabled = event.value)} />
<text-input value={text} onValueChange={event => (text = event.text)} />
<Slider bind:value={volume} minimumValue={0} maximumValue={1} />
```

Supplying your own `onValueChange` on a bound `Slider` silently disables the
`bind:` echo, so pick one form per instance. The full pattern, including
`$bindable()` for a wrapper component of your own, is in
[Two-way binding](/docs/howtos/two-way-binding/).

## Scoped styles (`<style>`)

A component's own `<style>` block is scoped by default, the same as real
Svelte — every class it declares gets a per-file scope suffix, resolved
through the same style registry every adapter's `class`/`className`/`:class`
path shares:

```svelte
<view class="card">
  <text>Scoped — no other component's .card collides</text>
</view>

<style>
  .card {
    padding: 16px;
    background-color: #13243a;
  }
</style>
```

`:global(.name)` escapes scoping the same way it does in real Svelte. Svelte's
own scoping deliberately doesn't reach into a child component's own markup —
scope a class where it's declared, not where it's used. `@keyframes` and
pseudo-class selectors are dropped with a diagnostic, since React Native has no
such concept. `@media`, `@container` and `var()` are kept and resolved on the
device, see [Media queries and variables](/docs/learn/media-queries-and-vars/).
See the [Styling guide](/docs/learn/styling/) for the full compiler
pipeline shared by every adapter.

## Runtime modules

`@symbiote-native/svelte` re-exports the same runtime utilities as the other
adapters, so app code keeps one import root: `Platform`, `StyleSheet`,
`PlatformColor`, `DynamicColorIOS`, `PixelRatio`, `Alert`, `Share`, `Linking`,
`Keyboard`, `Vibration`, `ActionSheetIOS`, `BackHandler`, `ToastAndroid`,
`PermissionsAndroid`, `AccessibilityInfo`, `I18nManager`, `Settings`,
`LayoutAnimation`, `InteractionManager`, `StatusBar`, `AppState`,
`findNodeHandle`, and `dlog`/`isDebug` for diagnostic logging. The CSS runtime
is there too: `matchMedia`, `setVariable`, `getComputedVariable` and
`registerProperty`, with the `useRootTag` rune that gives `setVariable` its
surface, see [Media queries and variables](/docs/learn/media-queries-and-vars/).

Two reactive reads are **runes** instead of hooks/composables — Svelte's own
term, and this adapter's lifecycle-helper bucket is named `runes/` to match:

```svelte
<script lang="ts">
  import { useWindowDimensions, useColorScheme } from '@symbiote-native/svelte';

  const dimensions = useWindowDimensions();
  const scheme = useColorScheme();
</script>

<text
  >{dimensions.current.width}×{dimensions.current.height} · {scheme.current}</text
>
```

Each returns a **boxed getter** (`{ get current() { ... } }`), not a bare
`$state` value — Svelte 5 reactivity is lexically scoped to the module that
declares it, so a raw `$state` returned from a function loses its reactivity
for the caller; read `.current` the same way you'd unwrap a Vue `Ref.value`.

Two more runes cover the common media features without a query string:

| Export                         | Value                                                                 |
| ------------------------------ | --------------------------------------------------------------------- |
| `orientation`                  | `.current` is `'portrait'` or `'landscape'`. A square window is portrait, as in CSS. |
| `createWidthQuery(bounds)`     | `.current` is `true` while the window width is inside `{ minWidth?, maxWidth? }`. Both bounds are inclusive, in points. |

```svelte
<script lang="ts">
  import { orientation, createWidthQuery } from '@symbiote-native/svelte';

  const wide = createWidthQuery({ minWidth: 600 });
</script>

<text>{orientation.current} · {wide.current ? 'wide' : 'narrow'}</text>
```

For any other feature (`prefers-reduced-motion`, `aspect-ratio`, `platform`), use `matchMedia`.

On Android, `Keyboard` and `Settings` do nothing until you also install
[`@symbiote-native/android`](/docs/packages/android/).
`keyboardDidShow`/`keyboardDidHide` never fire, because Android's only stock
keyboard-event source is `ReactRootView`'s layout listener. The bridgeless
surface SymbioteNative mounts never triggers it. `Settings` reads back `null`,
because RN's `Settings` has no stock Android implementation at all.

## Animations and gestures

An animated value dropped straight into a primitive's prop resolves in the
engine — `<view style={{ opacity: someAnimatedValue }} />` just works, no
wrapper component needed. `Animated` (both the JS and native driver) and
`PanResponder` are re-exported from `@symbiote-native/svelte` — see the
[Animations guide](/docs/learn/animations/) for the full surface.
`Animated.FlatList`/`Animated.SectionList` have no Svelte wrapper yet.

## Cross-surface content (`createTunnel`)

```svelte
<script lang="ts">
  import { createTunnel, TunnelIn, TunnelOut } from '@symbiote-native/svelte';

  const overlayTunnel = createTunnel(); // module-level singleton, importable from both surfaces
  let toastVisible = $state(false);
</script>

<!-- inside the surface that should paint the content -->
<TunnelOut tunnel={overlayTunnel} />

<!-- inside any other component, in any surface -->
{#if toastVisible}
  <TunnelIn tunnel={overlayTunnel}>
    <text>Toast</text>
  </TunnelIn>
{/if}
```

React's `createPortal` (and Vue's `Teleport`) have no Svelte twin at all.
`createPortal` is react-reconciler's own Fiber-level `HostPortal` primitive,
with no equivalent in a framework with no reconciler. Svelte has no built-in
`Teleport`-shaped relocation either. So `createTunnel` is the only
cross-surface primitive here, for two independently `mount()`-ed surfaces
that share no Fabric tree at all. `TunnelIn`/`TunnelOut` take an explicit
`tunnel` prop rather than `tunnel.In`/`tunnel.Out` member access like
React/Vue. A `.svelte` file compiles to one fixed, top-level component, so
there's no runtime factory to construct a fresh pair per `createTunnel()`
call the way Vue's `defineComponent` can.

## App entry point

```js
// index.js
import { createApp } from '@symbiote-native/svelte/bootstrap';
import App from './App.svelte';

createApp(App).mount('MyApp');
```

Mirrors React/Vue's `createApp(App).mount(appName)` two-step idiom. The
lower-level `AppRegistry`/`setHostRegistrar` entry point described in the
[Core API](/docs/api/core/#app-entry-point-appregistry) is also re-exported
directly, for app code that wants it. `AppRegistry.setWrapperComponentProvider`
is re-exported but currently **ignored** on this adapter. Vue composes a
wrapper via `h(wrapper, ...)` at call time. A compiled `.svelte` file has
no equivalent runtime composition of two independently-authored components,
so there's no working wrapper-component example to show here yet.

## Error boundaries (`<svelte:boundary>`)

Svelte 5's own `<svelte:boundary>` is currently **Svelte-exclusive** among the
five adapters — React's `componentDidCatch` boundary and Vue's
`onErrorCaptured` aren't documented patterns here yet:

```svelte
<svelte:boundary onerror={(error, reset) => console.error(error)}>
  <Child />

  {#snippet failed(error, reset)}
    <text>{error.message}</text>
  {/snippet}
</svelte:boundary>
```

Full behavior, including the `{@const}`-doesn't-capture-`reset()` gotcha: [How
to: catch render errors with `<svelte:boundary>`](/docs/howtos/error-boundaries/).

## Boundary

Do not pass React component packages to the Svelte adapter. A third-party
React Native package that ships a JavaScript React component still uses the
React dispatcher internally. Non-React adapters need native-view wrappers
instead — see the [Slider package](/docs/packages/slider/) for the reference
implementation, shipping on React, Vue, Angular, Svelte, and Solid alike.
