# RN behavior parity: checklist

Loop prompt (user, 2026-10-05): check EVERY primitive and its behavior against React Native; TDD with the vendored RN as the oracle; divergence = fix it (no waiting); Android AND iOS branches; RN tests we lack = port; a hook that demands a fix = do it; keep THIS list, do not trust memory. Opinion needed = `/grill-me`, do not wait.

No subagents inside this loop (user rule from the sibling API-parity initiative): work in the main turn.

## Procedure per primitive

1. Read RN source in the vendored checkout: `packages/react-native/Libraries/Components/<X>/` (both `.ios`/`.android` branches).
2. Read ours: `core/components/src/{behaviors,state,view}/`, the tag rule in `core/engine/cpp/SymbioteFabricProps.cpp`, adapter wrappers.
3. Diff prop defaults, platform branches, event handling, imperative methods.
4. List RN tests (`__tests__/*-test.js` Jest, `*-itest.js` Fantom) vs ours (`core/components/src/**/*.test.ts` vitest, `core/engine/cpp/tests/js/*.itest.ts`). Missing = port.
5. Divergence: failing test first, then fix. Record below.
6. Run: `pnpm vitest run <file>`; itests `node scripts/run-itests.mjs <file>` (iOS build) / `SYMBIOTE_ITEST_BUILD=build-android` for `*.android.itest.ts`. The Android arm is headless, never write "needs a device" for a branch in `SymbioteFabricProps.cpp`: add an `*.android.itest.ts` case. After ANY C++ edit rebuild both testers (`build`, and `build-android` via `pnpm run test:android` steps: the `-DANDROID` unit has its own `-Werror`, an iOS-only helper must sit under `#ifndef ANDROID`) and check the run prints no `CRASH` line (a stale `build-android` binary crashes on a missing hermes rpath and prints no FAIL).
