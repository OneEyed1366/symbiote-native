## Procedure per primitive

1. Read RN source in the vendored checkout: `packages/react-native/Libraries/Components/<X>/` (both `.ios`/`.android` branches).
2. Read ours: `core/components/src/{behaviors,state,view}/`, the tag rule in `core/engine/cpp/SymbioteFabricProps.cpp`, adapter wrappers.
3. Diff prop defaults, platform branches, event handling, imperative methods.
4. Close the RN test files of the subject in `ledger.md` (Jest `*-test.js`, Fantom `*-itest.js`) against ours (`core/components/src/**/*.test.ts` vitest, `core/engine/cpp/tests/js/*.itest.ts`). Missing = port.
5. Divergence: failing test first, then fix. Record in "Findings log".
6. Run: `node_modules/.bin/vitest run <file>`; itests `node scripts/run-itests.mjs <file>` (iOS build) / `SYMBIOTE_ITEST_BUILD=build-android` for `*.android.itest.ts`. The Android arm is headless, never write "needs a device" for a branch in `SymbioteFabricProps.cpp`: add an `*.android.itest.ts` case. After ANY C++ edit rebuild both testers (`build`, and `build-android` via `pnpm run test:android` steps: the `-DANDROID` unit has its own `-Werror`, an iOS-only helper must sit under `#ifndef ANDROID`) and check the run prints no `CRASH` line (a stale `build-android` binary crashes on a missing hermes rpath and prints no FAIL).
7. Five adapters: a behavior living in an adapter (not core) is checked in all five (React, Vue, Svelte, Solid, Angular), the Angular one against the post-merge element split (`adapters/angular/src/elements-*.ts`, `DECLARES_EVERY_PROP`).

## Standing user rulings (decisions, not statuses: they survive the reset)

- OUT OF SCOPE while RN keeps them `unstable_`: `unstable_VirtualView`, `VirtualViewMode`, the `virtualcollection` family (`unstable_VirtualArray` / `VirtualRow` / `VirtualColumn` / `VirtualColumnGenerator`, `unstable_createVirtualCollectionView`, `unstable_getScrollParent`), VirtualView itests (user 2026-10-07: "зачем они вообще?").

- SectionList-itest "list header wrapper has onLayout" is NOT added (RN writes `_headerLength` and never reads it).
- KEPT by the user: InputAccessoryView with no children mounts an empty zero-sized container (RN renders nothing); SafeAreaView on Android applies window insets (RN: plain View); `LayoutAnimation.setEnabled` really toggles (RN's is a self-assignment no-op).
- As RN (user): PanResponder grant leaves the touch accounting to capture/move; a Text press is lazy; Pressability has no radius fallback ("if RN can, we can"), moves are ignored until the frame is measured.
- Dropped / extracted: `DrawerLayoutAndroid` (CLAUDE.md), `ProgressBarAndroid`, `Clipboard` ("extracted from core" in RN 0.86). `renderScrollComponent` N/A (a third-party scroll component is a React component). Hover props N/A on native.
- PORT ALL missing RN exports in all 5 adapters (user 2026-10-06, "всё портировать"); `Animated.ScrollView` exists on Vue and Angular only by design (a `scroll-view` tag with `onScroll={Animated.event}` is the port elsewhere); nested lists follow RN's full `VirtualizedListContext` model; MVCP follows RN's `getDerivedStateFromProps` shift.
- KEPT by the user (2026-10-07): `onChangeText` on a `<text-input>` tag receives the event with `text` on it, not RN's bare string (Svelte's `target_handler` takes an object only, one contract on five adapters).
- Text ancestry is resolved once in the engine commit walk (`viewNameFor`); no per-adapter `TextAncestorContext`.
- DELIBERATE, veto-able, must be re-justified if met again: StyleSheet accepts any attribute name (no `X is not a valid style attribute`, RN's list cannot load headless); `new NativeEventEmitter()` without a module does not throw on iOS (`native-animated.ts` builds one with no module).
